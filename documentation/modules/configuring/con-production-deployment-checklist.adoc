= Production deployment checklist

Before deploying to production, review these security-relevant settings.
Most defaults are tuned for development convenience and should be hardened for production use.

== Authentication for external services

Both Loki and Prometheus default to `auth-mode=none`.
Configure authentication for production:

[source,bash]
----
# Loki: use ServiceAccount token (recommended for Kubernetes)
MCP_LOG_LOKI_AUTH_MODE=sa-token

# Prometheus: use ServiceAccount token
MCP_METRICS_PROMETHEUS_AUTH_MODE=sa-token
----

See xref:loki-authentication-{context}[Loki authentication] and xref:prometheus-authentication-{context}[Prometheus authentication] for all options.

== Rate limiting

All rate limits default to `0` (unlimited) in the server itself.
The `prod` and `prod-openshift` overlays set finite limits (30 log, 60 metrics and 120 general requests per minute, counted per pod and shared by all clients of that pod) through the `strimzi-mcp-defaults` ConfigMap.
Override them in the optional `strimzi-mcp-config` ConfigMap, which takes precedence.
The server uses three categories: `log` (log collection tools), `metrics` (metrics tools), and `general` (all other tools).
Set per-category limits to prevent resource exhaustion:

[source,bash]
----
MCP_GUARDRAIL_RATE_LIMIT_LOG_RPM=30
MCP_GUARDRAIL_RATE_LIMIT_METRICS_RPM=60
MCP_GUARDRAIL_RATE_LIMIT_GENERAL_RPM=120
----

See xref:rate-limiting-{context}[Rate limiting] for category definitions and default values.

== CORS origins

The default allows `localhost` and `127.0.0.1` origins on any port.
Override with your actual domain:

[source,bash]
----
QUARKUS_HTTP_CORS_ORIGINS=https://your-domain.com
----

See xref:cors-configuration-{context}[CORS configuration] for details.

== Network access and image tag

The MCP endpoint is unauthenticated.
The `prod` overlay ships a NetworkPolicy that admits only pods in the `streamshub-mcp` namespace.
Add a NetworkPolicy for the namespaces of your MCP clients, gateway, ingress controller, or Prometheus (when a PodMonitor scrapes the server; admit it on port `management` (9000) only) as needed.
The `prod-openshift` overlay (OpenShift 4.20 or later) additionally admits the OpenShift router and cluster monitoring, which exposes the unauthenticated endpoint through the Route to anyone who can reach the router.
Put an authenticating front (for example an OAuth proxy) in front of the Route, or remove the Route and use port-forwarding.

When upgrading an existing deployment across the 0.3.0 boundary, apply the new manifests and the new image together: the updated probes target the `management` container port (9000), which only the new image opens, and the new image no longer serves `/q/*` on the `http` port (8080), so a mixed state — old image with new manifests, or new image with old probes — never becomes ready.

The base manifests reference `quay.io/streamshub/strimzi-mcp:latest`, which Kubernetes pulls on every pod start.
Release tags set the image tag to the release version in `base/kustomization.yaml`; when deploying from a clone, pin the tag yourself:

[source,bash]
----
cd install/strimzi-mcp/base
kustomize edit set image quay.io/streamshub/strimzi-mcp=quay.io/streamshub/strimzi-mcp:<version>
----

== Metrics provider permissions

The default `streamshub-pod-scraping` metrics provider needs `pods/proxy` access, which is not part of the base ClusterRole.
Either apply the optional sensitive Role in each Kafka namespace (see xref:proc-configuring-rbac-installing[Configuring RBAC]) or switch to the Prometheus provider.

== Log redaction

Log redaction is enabled by default and redacts common credential patterns.
Add custom patterns for organization-specific secrets:

[source,bash]
----
MCP_GUARDRAIL_LOG_REDACTION_CUSTOM_PATTERNS_0='(?i)x-internal-token:\s*\S+'
----

See xref:log-redaction-{context}[Log redaction] for built-in patterns and configuration.
